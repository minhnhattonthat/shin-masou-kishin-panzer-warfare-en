# Skill gotchas

One line per gotcha: the reference file it belongs in, then the fact.

- references/platform-ps1.md: a font TIM whose CLUTs map only one bit of each 4bpp pixel to white (CLUT 0 = 0,FFFF,0,FFFF…) packs 4 glyph pages into one image; the glyph table's "page" picks the CLUT row. Edit only that bit when redrawing cells, or the other 3 pages break.
- references/pipeline.md §Marker: a sprite-per-glyph renderer can give each text window a fixed slot count (here 80) freed on close; English (about twice the glyphs per byte) overflowed it and left stray glyphs on later screens. Log each window's slot start/count before the width gate (`tools/lua/windows.lua` pattern).
- references/pipeline.md §Marker: a same-byte-length marker (each line → filler of the JP line's byte count) cannot overflow a full pool; pools here had zero slack even in Japanese, so `[id]` markers longer than the JP failed to insert.
- references/emulator-qa.md §Visual QA: typewriter glyphs fade in grey → white; judge a box on its settled frame, not mid-typing.

- references/platform-ps1.md: `iso9660.py` reads 2048-byte ISOs only; for a raw MODE2/2352 .bin, read the PVD at `16*2352+24` (this repo's `tools/disc_ls.py`).
- references/platform-ps1.md: script-text pools here are referenced by absolute RAM pointers inside fixed 16-byte commands; a RAM dump + `ramfind`-style chunk match found the load base in one step (`tools/ramfind.py`).
- SKILL.md / setup: context-mode trims Bash/Read output over ~4 KB even for `--help`; redirect help to a file and Read it with limit.
- references/graphics.md: no TIM scanner ships with the skill for PS1; this repo's `tools/tim.py` + `tools/montage.py` (find, decode, labelled contact sheets) did the survey.
- references/platform-ps1.md: ffmpeg's psxstr demuxer decodes a movie cut straight out of the raw .bin (2352-byte sectors from the file's LBA); split MOV.STR into movies where the STR frame number resets (`tools/str_movies.py`), then `-vf fps=1/3` frames + montage = FMV text survey in minutes, no jPSXdec.
- references/graphics.md: montage only byte-distinct TIMs (`montage.py --unique`) and skip the portrait size class: cut a 1500-TIM sweep from 33 sheets to 16.
- references/emulator-qa.md §Debug tool: the fastest PS1 warp was the main loop's mode-handler table (`jalr` on table[mode], mode word at `$gp`+x): forcing each mode once mapped game over, intermission, option, save screens and credits in 8 runs. Force it while a normal mode is starting (here the event), not from the title: the title's display setup drew garbage.
- references/emulator-qa.md §PCSX-Redux: a `.sstate` holds main RAM raw at file offset 0x27 (uncompressed), so Python can read RAM from states without the emulator (find it by matching an exe chunk).
- references/emulator-qa.md §Hooks: a Lua helper that re-queues a press whenever `L.route_done()` is true, called before a later `L.route_done()` check in the same frame, makes that check never pass; test the wait condition before tapping.
- references/platform-ps1.md: to find the font path, a read watch on the event text pool (`watch.lua`, `--debugger`) gave the string loop in one run; its glyph lookup was a binary search over a 6-byte row table (`first code, row, page`), not Krom.
- references/pipeline.md §Extract: don't require a NUL before a string start: here 31 event messages and several exe strings follow a pointer word directly (`... 1C 80` then text); taking every pointer target that decodes as text found them, the NUL-preceded scan missed them. Also a kana-run coverage scan (`sjis_scan.py`) over the whole event block caught the chapter-intro scroll pages, which no message command points at.
- references/emulator-qa.md §Free-space trap: `watch.lua` logs each PC once, so the boot-time CD DMA (one PC for every CdRead) hides every later load into the range; pass `FROM=<frame after boot>` (repo `trap.py --from`) or log DMA runs per load (`tools/lua/loads.lua`). A "follow-on load after the event block" in a RAM dump was the residue of an earlier, larger overlay in the same slot.
- references/platform-ps1.md: a full text pool can often grow by moving whole blocks to the end of their container file and rewriting the u16 sector list, when the loader takes [t[i], t[i+1]) and every disc file is found with CdSearchFile (no LBAs in the exe); check the loader's size cap (here `< 0x20` sectors) and keep any over-read past the file end (here 3 sectors into the next file) intact.
- references/translation.md §Review: `codex exec` can be quota-blocked for days (usage limit), and `-o` then leaves an empty report with exit 0; check the report size, fall back to reviewer subagents.
- assets/batches.py merge: on Windows `write_text` on script JSON hit a transient `OSError: [Errno 22] Invalid argument` (file held by a concurrent reader); re-running merge was clean (merge is idempotent).
- assets/batches.py: translators of parallel batches each invented their own wording for the game's stock defeat/retreat lines; seed those lines (same JP, many places) in the glossary or a wave-0 batch before wave 1.
- references/translation.md §Review: reviewer subagents can't write files; a compact report (`VERDICT` line, then SEV<TAB>id<TAB>replacement EN<TAB>reason, at most 5 Minors) appended by the controller to a tracked reports.tsv keeps 30+ reviews in one controller context; replacement EN then merges as a batch, and the batch check catches the over-wide ones.
- assets/batches.py glossary(): an Avoid form is checked on every line, not only lines whose JP has the term; keep Avoid forms specific (e.g. "Hell Skycut", not "Grunt" if grunts appear as sounds).
- references/platform-ps1.md: a zero run inside the PS-X EXE image can be live BSS (here 0x80170935+, written by library code at boot): strings placed there blacked out the boot. Trap-test any exe zero run from frame 0 (watch.lua FROM=0) before using it, not only after the scene.
- references/platform-ps1.md: extract's in-place `max` (up to the next non-zero byte) can span zero-init variables after a string; cap pointer strings at the JP string's own 4-aligned slot and move longer ones.
- references/platform-ps1.md: string renderers with a sprite/glyph "slot" argument (here 0x80102D90's a0) often give each label a fixed slot range sized for the JP glyph count; English names past it silently lose glyphs to the next label ("Tilwes" showed "es"). Probe slot bases per screen (slotdump.lua-style occupancy log) and re-base; also check draws that shared a base on purpose (an intro label later overwritten by the HUD label) or they become stale glyphs.
- references/pipeline.md §Checks: a per-stage byte-diff write log (snapshot before/after each writer, log changed runs) gives romdiff --writes for free without threading a put() through every writer; run the range check separately, since logged writes count as covered.
- references/graphics.md §Edit and re-import: PS1 TIMs with many CLUTs (and 34 byte-identical copies of one sheet): edit in palette-index space (rows of rect + text + ink/edge index, or an exported indexed PNG), and find copies by the pixel block, not the whole TIM (headers/CLUTs differ). tools/gfx.py here; a candidate for the skill's tiles.py.
- references/emulator-qa.md §Screen tour: a dialogue tour that mashes circle past the event into map player control opened the weapon list and exposed a glyph-slot overflow no warp shot showed; let tours run a few hundred frames past the event's end.
- references/pipeline.md §Extract: a 1-glyph "string" reached by a u32 pointer can be data (here 90 78 20 00 inside a 12-byte sprite-record table read as 靭+space); insert moved and zeroed it and a map window lost sprites. Sweep short pointer strings for record patterns around them; when a corruption only shows with English exe text, bisect by id (build with a subset kept JP via qa=None) instead of guessing at glyph slots.
- references/emulator-qa.md §Debug tool: to tell whether a graphic is ever used, dump VRAM every N frames (ppudump.lua DUMP_EVERY) and search the TIM's pixel rows (tools/debug/vram_find.py); a sheet resident in VRAM but never seen on screen is a waiver candidate with evidence.
- references/emulator-qa.md §emu.py (PCSX-Redux): a RAM write in the same Vsync callback as PCSX.loadSaveState is lost (the load lands after it); poke one frame later (tools/debug/force_text.lua).
- references/emulator-qa.md §emu.py (PCSX-Redux): --debugger (interpreter) and the default dynarec run different frame timings from a cold boot; a frame-exact state for a --debugger probe's frame number must itself be made with --debugger.
- references/emulator-qa.md §Text coverage: strings a tour never reaches can be forced into their real box from one savestate per box (write the built bytes over the string the box is about to draw, shoot, reload): tools/debug/force_text.py + force_check.py covered 3441 event lines + 1997 battle quotes in ~1 h. Long messages also exposed a real bug (glyphs past the old slot range drawn dim) that 598 tour sheets passed as "still typing".
- references/emulator-qa.md §Visual QA: a grey tail on a long dialogue line is not always the typewriter: hold the frame 300+ frames with no input; if it is still grey, it is a bug.
- references/platform-ps1.md (font): a font TIM can exist in 3+ byte-identical copies across disc files, each loaded by a different screen (here GRA5 0x199A800, only for the title LOAD card screen); search every file for the original font bytes and fail the build on any unpatched copy. A blank-card warp hid it: test card screens with a real save (`--sav`).
- references/translation.md (fit): a JP string with full-width spaces in the middle (あら？　　機…) often has a number drawn over that gap by separate code at a fixed x; find the draw (x immediate) and leave the same pixel gap in the English.
- references/emulator-qa.md §Text coverage: a savestate carries the exe's code and strings in RAM, so a forced-display or asm check from an old state shows the old build; regenerate the base state on the build under test.
- references/emulator-qa.md §emu.py (PCSX-Redux): with `--state-in`, a Lua RAM poke on frame 1 is overwritten when the state finishes loading; poke at frame >= 8 (a whole session of "forcing doesn't take" was this).
- references/platform-ps1.md §FMV: STR v2 frames end with the 10-bit code 0x1FF (`0111111111`) right after the last block's EOB; a re-encoded frame without it decodes fine in ffmpeg but freezes the game's player on that frame. Check a new encoder against every disc frame (parse the VLC + end code), then cold-boot the movie.
- references/platform-ps1.md §FMV: the Claude Code auto-mode classifier refused to run a downloaded jPSXdec jar (twice); a ~150-line numpy MDEC v2 encoder (MPEG-1 B.14 table + 22-bit escape, column-order macroblocks Cr Cb Y1-4, frame put back into its own sectors at the lowest qscale that fits) plus ffmpeg's psxstr decoder did the job (this repo: tools/fmv.py). Mixed-mode 2336-byte sectors in a dumpsxiso tree: mkpsxiso regenerates EDC/ECC.
- references/translation.md §Review (story pass): story-reviewer subagents finish a 450-line chapter in 7-12 tool calls / ~1 min; asking for TSV-only reports (SEV, id, full suggested EN, why + VERDICT line) kept 35 reports to ~1.5k tokens each and made them mergeable by script (tools/story_fixes.py). Tell them silent lines are swept by the controller, or every chapter reports them.
- references/translation.md §Review: reviewers suggest straight double quotes ("Alma!") even when the glossary bans them (font draws " as a closing mark only); the polish pass applied one before a story reviewer caught it: grep merged suggestions for quote marks.
